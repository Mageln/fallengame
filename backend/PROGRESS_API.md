# Серверный прогресс — начальный этап

**Экспериментальное подключение, не готово к выпуску.** По умолчанию игра по-прежнему использует localStorage. При сборке с `VITE_SERVER_PROGRESS=true` клиент загружает состояние и отправляет действия в API; он не читает и не перезаписывает локальный прогресс и не переходит на него при ошибке сети. Старые сохранения остаются в браузере. Сервер создаёт нового персонажа с нуля. Не включайте режим для игроков до переноса и проверки всей экономики, боёв, рейдов, кланов и платежей.

Новая таблица `PlayerProgress` независима от старых таблиц `User`, кланов и покупок. При первом `GET /api/progress` создаётся состояние с начальными значениями, без импорта локальных сохранений. Обязателен `X-VK-Launch-Params` с проверяемой подписью VK. Секрет хранится только на сервере. `POST /api/progress/action` принимает `{ "revision": 0, "action": { "type": "SET_APPEARANCE", "appearance": 1 } }`. При устаревшей версии ответ 409; клиент должен заново загрузить состояние, а не перезаписывать его. На сервере уже обрабатываются внешний вид и обучение, часть улучшений, задания, ежедневные награды, магазин и экипировка. Разрешены только явно перечисленные действия; клиент не может передать состояние, цену, награду или время. Остальные действия, включая бои, рейды и кланы, пока запрещены. Реальных платежей и выдачи премиум-валюты нет. Энергия восстанавливается по серверному времени, а не по запросу клиента; суточные награды используют часовой пояс сервера (для единообразия задайте TZ=UTC). Изменять таблицу напрямую может только сервер.

Для запуска нужна существующая или новая база PostgreSQL с применённой базовой миграцией проекта: `npm ci`, `npm run db:generate`, `npx prisma migrate deploy`, `npm run build` из папки backend. Настройте `DATABASE_URL`, `VK_APP_SECRET`, `VK_APP_ID` и разрешённый origin (`VITE_APP_URL`); не публикуйте секреты. Для существующей базы сначала сделайте резервную копию и проверьте историю миграций. Не применяйте начальную миграцию проекта поверх уже существующих таблиц.

Дальнейшая работа: перенести на сервер и покрыть тестами оставшиеся игровые правила и таймеры, защиту от повторных действий и конкурентных запросов, покупки и подтверждение платежей, общие кланы; согласовать существующие серверные данные с новой моделью. Проверить подключение клиента, после чего проверить реальную авторизацию VK, миграции и многопользовательские сценарии на тестовой базе. Локальные сохранения не удаляются автоматически.

## Проверка клиентского подключения

Нужны миграции `20261105_player_progress` и `20261106_progress_energy`, сгенерированный клиент Prisma и запущенный backend с `VK_APP_SECRET` и `VK_APP_ID`. Из корня проекта для локального Vite можно запустить `BACKEND_PROXY_TARGET=http://127.0.0.1:3001 VITE_SERVER_PROGRESS=true npm run start`. Браузер использует относительный `/api/progress`, а Vite пересылает запрос в backend. Для VK нужен действительный подписанный набор параметров запуска; простой заход в браузере без VK не авторизуется. Для работающей игры у пользователей необходим доступный по HTTPS сервер и соответствующая настройка маршрута на хостинге.

Запросы действий идут последовательно с версией сохранения. Если ответ потерялся или поступил конфликт версии, очередь блокируется до явного обновления состояния; неизвестное действие повторно не отправляется автоматически. Неподдерживаемые действия показывают ошибку. В этом режиме энергия обновляется при следующем действии или по кнопке «Обновить с сервера».
