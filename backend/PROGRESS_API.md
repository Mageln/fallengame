# Серверный прогресс — начальный этап

**Не подключено к клиенту и не готово к выпуску.** Игра по-прежнему сохраняется в localStorage. Не называйте это серверным сохранением игроков и не переключайте production на этот API до переноса и проверки всей экономики, платежей и игровых действий.

Новая таблица `PlayerProgress` независима от старых таблиц `User`, кланов и покупок. При первом `GET /api/progress` создаётся состояние с начальными значениями, без импорта локальных сохранений. Обязателен `X-VK-Launch-Params` с проверяемой подписью VK. Секрет хранится только на сервере. `POST /api/progress/action` принимает `{ "revision": 0, "action": { "type": "SET_APPEARANCE", "appearance": 1 } }`. При устаревшей версии ответ 409; клиент должен заново загрузить состояние, а не перезаписывать его. Сейчас разрешены только внешний вид и шаги обучения; действия с валютой, наградами и произвольное состояние намеренно запрещены. Изменять таблицу напрямую может только сервер.

Для запуска нужна существующая или новая база PostgreSQL с применённой базовой миграцией проекта: `npm ci`, `npm run db:generate`, `npx prisma migrate deploy`, `npm run build` из папки backend. Настройте `DATABASE_URL`, `VK_APP_SECRET`, `VK_APP_ID` и разрешённый origin (`VITE_APP_URL`); не публикуйте секреты. Для существующей базы сначала сделайте резервную копию и проверьте историю миграций. Не применяйте начальную миграцию проекта поверх уже существующих таблиц.

Дальнейшая работа: перенести на сервер и покрыть тестами все игровые правила и таймеры, защиту от повторных действий и конкурентных запросов, покупки и подтверждение платежей, общие кланы; согласовать существующие серверные данные с новой моделью. Подключить клиент к API с обработкой конфликтов и недоступности сервера, после чего проверить реальную авторизацию VK, миграции и многопользовательские сценарии на тестовой базе. Локальные сохранения не удаляются автоматически.
