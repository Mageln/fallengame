# API убежищ выживших

Серверные кланы пока не подключены к интерфейсу игры. Создание клана списывает припасы из серверного `PlayerProgress.state.gold`, а не из браузера или старого `User.gold`. Остальной серверный API кланов и данные `User` пока не объединены с клиентом; рейтинг не готов к выпуску.

## Запуск на новой базе PostgreSQL

1. В `backend/.env` задайте `DATABASE_URL`, `VK_APP_SECRET` (секрет приложения VK) и, по желанию, `VK_APP_ID`, `VITE_APP_URL`. Не помещайте секрет в переменные `VITE_*` или клиентский код.
2. `npm install --prefix backend`
3. `npm --prefix backend run db:generate`
4. Из каталога `backend`: `npx prisma migrate deploy` — применяет **первую** миграцию только к новой базе. Если уже есть данные/схема, сначала подготовьте отдельную инкрементальную миграцию; исходную миграцию поверх существующих таблиц применять нельзя.
5. `npm --prefix backend run dev`

Обработчики создания и прогресса требуют заголовок `X-VK-Launch-Params` со строкой подписанных параметров запуска VK (например, `window.location.search`). Сервер проверяет подпись, приложение и срок действия параметров; `vkId` из тела запроса не используется. Для создания убежища нужно сначала загрузить серверный прогресс через `GET /api/progress` и иметь в нём не менее 2500 припасов. Профиль `User` создаётся в той же транзакции при необходимости. Демонстрационная покупка отключена во всех окружениях до подключения подтверждения оплаты VK.

## Маршруты

Все маршруты доступны с префиксом `/clans`, `/api/clans` и прежним `/api/clan`.

- `POST /clans/create` — `{ "name": "Последний рубеж", "emblem": "skull" }`; транзакция проверяет уникальное имя и баланс, списывает ровно 2500, назначает создателя лидером. Эмблемы: `skull`, `axe`, `mask`, `fuel`.
- `GET /clans/leaderboard?sort=rating&page=1&limit=20&search=...` — `{ items: [{ rank, id, name, emblem, members, rating }], total, page, limit }`. Сортировка: рейтинг по убыванию, затем имя.
- `GET /clans/{id}` — описание, состав, рейтинг и прогресс контрактов; лидеру, передавшему подписанные параметры, доступны заявки.
- `POST /clans/{id}/apply` — подать заявку.
- `POST /clans/{id}/applications/{userId}/resolve` — `{ "accept": true | false }`; только лидер.
- `POST /clans/{id}/tasks/{taskId}/progress` — отключён (501 для валидного запроса): клиент не может подтвердить реальность события. Контракты будут учитываться после интеграции с серверными игровыми событиями.

**До запуска общего рейтинга** прогресс-контрактов должен поступать из серверной логики боёв/рейдов/крафта, а не из произвольных запросов клиента. Прямой клиентский маршрут отключён; атомарная обработка событий ещё не реализована.
