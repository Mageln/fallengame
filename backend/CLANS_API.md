# API убежищ выживших

Клиент игры пока хранит припасы и кланы в браузере. Серверный API ниже — отдельный, авторитетный источник данных для подключения общего рейтинга: браузерное золото **не синхронизируется** с `User.gold` в PostgreSQL. Нельзя выдавать локальную доску за общий рейтинг. До интеграции всех серверных игровых наград не переключайте UI на серверный режим.

## Запуск на новой базе PostgreSQL

1. В `backend/.env` задайте `DATABASE_URL`, `VK_APP_SECRET` (секрет приложения VK) и, по желанию, `VK_APP_ID`, `VITE_APP_URL`. Не помещайте секрет в переменные `VITE_*` или клиентский код.
2. `npm install --prefix backend`
3. `npm --prefix backend run db:generate`
4. Из каталога `backend`: `npx prisma migrate deploy` — применяет **первую** миграцию только к новой базе. Если уже есть данные/схема, сначала подготовьте отдельную инкрементальную миграцию; исходную миграцию поверх существующих таблиц применять нельзя.
5. `npm --prefix backend run dev`

Обработчики создания и прогресса требуют заголовок `X-VK-Launch-Params` со строкой подписанных параметров запуска VK (например, `window.location.search`). Сервер проверяет подпись, приложение и срок действия параметров; `vkId` из тела запроса не используется. Для создания убежища пользователь должен уже существовать в серверной таблице `User` и иметь на **серверном** балансе не менее 2500 золота. Демонстрационная покупка в production отключена до подключения подтверждения оплаты VK Pay.

## Маршруты

Все маршруты доступны с префиксом `/clans`, `/api/clans` и прежним `/api/clan`.

- `POST /clans/create` — `{ "name": "Последний рубеж", "emblem": "skull" }`; транзакция проверяет уникальное имя и баланс, списывает ровно 2500, назначает создателя лидером. Эмблемы: `skull`, `axe`, `mask`, `fuel`.
- `GET /clans/leaderboard?sort=rating&page=1&limit=20&search=...` — `{ items: [{ rank, id, name, emblem, members, rating }], total, page, limit }`. Сортировка: рейтинг по убыванию, затем имя.
- `GET /clans/{id}` — описание, состав, рейтинг и прогресс контрактов; лидеру, передавшему подписанные параметры, доступны заявки.
- `POST /clans/{id}/apply` — подать заявку.
- `POST /clans/{id}/applications/{userId}/resolve` — `{ "accept": true | false }`; только лидер.
- `POST /clans/{id}/tasks/{taskId}/progress` — `{ "amount": 1, "eventId": "unique-game-event-id" }`; участник клана может записать событие. Повторный `eventId` не начислит рейтинг снова. Контракты: `clear_streets`, `clan_raids`, `medkit_stock`, `barricade`. Очки присваиваются один раз за ежедневный/еженедельный период; рейтинг = очки заданий + 25 за участника.

**До запуска общего рейтинга** прогресс-контрактов должен поступать из серверной логики боёв/рейдов/крафта, а не из произвольных запросов клиента. Нынешний маршрут ограничивает и дедуплицирует входящие события, но не способен самостоятельно подтвердить факт боя, пока игровой процесс существует только в локальном состоянии браузера.
