# VK Mini Apps: ключи и авторизация

## Серверное сохранение

В серверном режиме бэкенд идентифицирует игрока по подписанным параметрам запуска VK, которые клиент передаёт в заголовке `X-VK-Launch-Params`. Подпись проверяется на сервере с помощью **защищённого ключа приложения** (`VK_APP_SECRET`). Это не то же самое, что сервисный ключ доступа (`VK_SERVICE_TOKEN`): подставлять сервисный токен вместо секрета нельзя. Для API сохранения `VK_SERVICE_TOKEN` не используется.

В `backend/.env` задаются `DATABASE_URL`, `VK_APP_SECRET` и `VK_APP_ID`; секретные значения нельзя публиковать, добавлять в Git, передавать в клиентские переменные `VITE_*` или присылать в чат. `VITE_VK_APP_ID` на клиенте — публичный ID приложения, не секрет. Пример без реальных ключей:

```env
DATABASE_URL="postgresql://..."
VK_APP_ID="ID_ПРИЛОЖЕНИЯ"
VK_APP_SECRET="ЗАЩИЩЁННЫЙ_КЛЮЧ_ПРИЛОЖЕНИЯ"
```

Проверка в `backend/src/vkAuth.ts` дополнительно требует `vk_ts` не старше 24 часов. Совместимость этого ограничения с фактическими параметрами запуска вашего приложения VK ещё нужно проверить; не отключайте проверку подписи для обхода ошибок авторизации. Серверное сохранение и перенос игровой логики пока экспериментальные: состояние работы описано в `backend/PROGRESS_API.md`.

## Запросы к VK API от имени пользователя

`src/services/vkApi.ts` получает пользовательский токен через VK Bridge и хранит его только в памяти для запросов друзей. Токен может истечь или быть отозван; приложение повторно запрашивает его при ошибке авторизации. Не сохраняйте его в `localStorage`, журнале или репозитории. Не следует предполагать универсальное время действия токенов или наличие автоматического refresh для всех способов авторизации.

Сервисный ключ применяют только для тех серверных методов VK API, которые его поддерживают, и только при необходимости. Токены в URL могут попасть в журналы; не выводите полные запросы и секреты в логи. Используйте HTTPS. Правила и доступность методов сверяйте с актуальной документацией VK.

## Сохранения

При обычном запуске игра всё ещё использует локальное хранилище браузера; оно не синхронизируется между устройствами. Экспериментальный `VITE_SERVER_PROGRESS=true` использует PostgreSQL через бэкенд и не импортирует локальные сохранения. Не включайте этот режим для игроков, пока перенос и проверки не завершены.
